Campus BusCampus Bus

Campus Bus is a desktop seat-reservation system for a college's buses. It is Java: a Swing window hosts a JavaFX WebView, the screens are HTML, CSS and JavaScript, and MySQL 8 stores everything and enforces the booking rules. Students pick a trip and a stop, choose a seat and get a pass; the transport office runs routes, fleet and passengers.

shipped, v1.1 (2026-10-18)

Tried on one Windows 11 PC so far.

Why it exists

Handled by hand, nobody knows which seats are free, when the bus reaches a stop, or who is on which bus.

From the problem statement in the README.

What I built

Built solo: the Java model and booking rules, the JDBC and MySQL layer, the HTML screens and the bridge to them, the PDF pass and confirmation email, a hand transcription of the SCMS bus schedule (21 buses, 259 boarding points), the Windows setup scripts and packaging, and the tests.

GitHub lists one contributor on the repository.

How it's put together

  • Entry Main.java, gui/LoginFrame.javaMain prepares database connectivity and opens the login window. LoginFrame gets a User back and calls user.openDashboard(), so a student and an admin take the same path to different windows.
  • Model model/User, with Student and Admin below it; Bus, Route, Timetable, Reservation. Fields are private and changes validate first: Student.updateStudent() rejects a 9-digit phone, and Timetable refuses an arrival window that ends after classes start.
  • Booking rules service/ReservationService.javaApplies the booking rules. A booking locks the student and the bus while it is checked and saved.
  • Persistence dao/, database/schema.sqlStudentDAO, AdminDAO, BusDAO and ReservationDAO run SQL through JDBC against MySQL. Tables: students, admins, settings, routes, buses, reservations.
  • Screens gui/WebPanel.java, gui/WebBridge.java, resources/web/WebPanel is a Swing JFXPanel hosting a WebView and exposing a Java object as window.app. JavaScript asks, Java checks the signed-in role, applies the rules, reads MySQL and returns JSON. JavaScript draws the route line, the seat grid and the pass.
  • Pass and email service/PassPdf, PassImage, SmtpMailThe PDF is a picture of the pass the app shows, drawn off-screen from the same data, so the same booking gives the identical PDF whether emailed or saved.
  • Schedule import service/ScheduleImport.javaAdmin, Routes, Import schedule reads a text file of routes, stops and printed times. It is idempotent and checked by reading back.
  • Windows release scripts/, packaging/The logic behind the three .cmd files is in the PowerShell script. The zip carries a Java 25 runtime made with jlink.

Decisions, and why

  1. Double-booking is blocked by MySQL itself, not only by the Java check.

    reservations.active is a generated column: 1 while BOOKED, NULL once CANCELLED. UNIQUE (bus_id, travel_date, direction, seat_no, active) allows one booked row per seat, while cancelled rows never clash, so a cancelled seat can be booked again. A second unique key stops one student holding two seats in the same direction on the same day.

  2. The role check lives in the Java bridge, not only in the menus.

    Student sessions cannot invoke admin operations or receive other students' names. The separation is enforced in Java, not just hidden in the UI.

  3. Printed times are kept exactly, and a stop with no printed time is shown as an estimate.

    The timetable never moves a printed time. Where the schedule gives no campus arrival, the window's end is shown as a target, never as a printed time.

  4. "Where's my bus" is an estimate from the timetable, not a tracker.

    The buses carry no GPS, so the position is worked out from the timetable and refreshed every 30 seconds.

  5. The release ships as a zip of scripts on a signed Java, not as an .exe.

    An unsigned .exe was blocked by Windows Smart App Control in testing, while the bundled Java's javaw.exe is signed by the Eclipse Foundation and starts normally.

  6. Setup installs a private MySQL for the Windows user, local connections only.

    It downloads MySQL 8.4.11 and refuses it unless the SHA-256 matches, needs no admin rights, listens on 127.0.0.1:3310, and generates the demo passwords on the user's own computer.

  7. The confirmation email never decides whether the booking happened.

    The email runs on a background thread after the booking is saved, and reservations.email_status records it apart from the booking. If mail is not set up or fails, the booking stays confirmed and Save pass (PDF) still works offline.

The interesting problems

  • Booking and admin races

    RegressionTest has one test per defect from the October 2026 audit, including four booking and admin races and a route edit racing a booking. The fix is locking: a booking holds the student and the bus while it is checked and saved, row locks are waited for at most 10 s, and then the user sees "busy, try again" with nothing saved. The README records the 14 audit tests as each failing on the v1.0 code.

  • An unsigned .exe that Windows would not run

    It was blocked by Smart App Control, so the release has no CAMPUS BUS.exe and starts through run-campus-bus.cmd and the signed javaw.exe instead.

  • Install folders with accents

    A full setup from the release zip was run under a user folder called "José Test", with a space and an accent, and there is a regression test for accented install folders.

  • A refusal hidden behind an older message

    An admin refusal could be covered by a still-visible "saved". In v1.1 a new message replaces the one on screen.

How it's tested

v1.1 release verification: 166 tests (87 + 37 + 26 + 2 + 14), 0 failures, 0 skipped, against an isolated MySQL 8.4 on port 3320 with email switched off. On one Windows 11 PC, in a sandbox: setup, repeat setup, the missing-settings guard (nothing deleted), recovery from an interrupted setup, launch, admin sign-in and messages, and clean shutdown.

mvn clean test. ModelTest (87, no database); DatabaseTest (37, real JDBC on college_bus_test, reset from schema.sql before each test); RegressionTest (26); WebBridgeTest (2); NotificationTest (14, with a fake mail provider, so nothing real is sent). Without a reachable MySQL the database tests are skipped, not failed: for v1.0, a clean clone without settings ran 124 tests with 0 failures and 37 skipped. The pre-v1.0 audit also walked 73 controls in the running app: 69 pass, 3 untested, 1 blocked, 0 fail.

Limits I've written down

  • One Windows 11 PC. Windows 10, a second physical PC and other antivirus or SmartScreen setups are unverified, and so is Import schedule through the Windows file picker.
  • The release is not code-signed, so SmartScreen may ask for confirmation on the .cmd files. First setup needs internet and about 1 GB of disk.
  • Every installed copy holds the MySQL user and password in db.properties. A server API would be needed to remove that; the audit calls it medium severity for a desktop app.
  • The private database belongs to the first window you open: closing that window stops it, also for a second window still open.
  • It is a desktop program, not a web service, and buses have no GPS.
  • Keyboard-only use is incomplete: the Student/Admin switch, the left menu and Log out need the mouse.
  • Database calls still run on the screen's thread, so a slow database pauses the window, for at most about 15 seconds.
  • "Sent" means Gmail accepted the email, not that it reached the inbox.
  • Five SCMS routes still need confirming with the transport office (docs/scms-import-report.md).
