Event HorizonEvent Horizon

Event Horizon is a browser physics sandbox where you place gravity wells, black holes, supernovas, repulsors and orbiting bodies and watch the universe respond. The simulation runs on a fixed 1/60 s clock separate from the Three.js/WebGL renderer, with six seeded starting worlds and pause, rewind, undo, checkpoints and local saves.

shipped, live

The app still calls itself GOD MODE.

Why it exists

Built around one simple idea: give people the tools to disturb a universe, then let gravity tell the rest of the story.

What I built

Built solo: design, deterministic physics core, WebGL renderer and shaders, procedural audio, the Orbito companion, test and benchmark harnesses, and the Vercel deploy.

GitHub lists one contributor on the repository.

How it's put together

  • Simulation core src/core/Physics, particles, worlds, scenarios, events, objectives, history and serialization. Independent of the renderer.
  • Renderer src/render/Three.js renderer, shaders (renderer.ts, shaders.ts) and camera.
  • Input src/input/interaction.tsPointer, mouse and touch interactions for the seven tools.
  • Audio src/audio/audio.tsProcedural Web Audio: ambient layers and event sounds.
  • Orbito companion src/orbito/brain.ts (moods, reactions), knowledge.ts (answers from live universe state), voice.ts (browser speech), orbito.ts (view).
  • Orchestration src/app.tsCoordinates simulation, rendering, input, history and persistence.

Decisions, and why

  1. Slingshot is detected in two phases: close approach, then outbound escape.

    A circular orbiter is not a slingshot; the detector must see an actual flyby (and it avoided false discoveries during scenario loading).

  2. Quality levels are rendering-only, and the 6,000-particle trim in performance mode was removed.

    The trim silently mutated the simulation; rendering-only tiers keep physics deterministic.

  3. Adaptive Auto quality uses a rolling P95 frame-time controller with hysteresis and cooldown.

    Graceful adaptation to stronger or weaker hardware without rapid oscillation.

  4. Benchmarks read the WebGL renderer string from the app's own context and label every run with GPU, quality, scenario and duration.

    Honest, reproducible performance claims: the label is read from the driver, never assumed.

The interesting problems

  • Rewind slider race (defect D-1)

    syncUi() was throttled to 110 ms, so a keyframe pushed mid-frame could be visible in state before the slider's max updated. A repro script showed 4/6 immediate-read failures on the baseline build. Fix: force one syncUi() whenever the keyframe count changes; 0/5 failures and 0 ms lag after.

  • Reaching the right GPU for benchmarks

    --use-angle=d3d11 selected the integrated Radeon 740M; the RTX 3050 was only reachable through Vulkan-over-ANGLE, confirmed by the unmasked renderer string (scripts/probe-gpu2.mjs).

  • Conservation in mergers and accretion

    Mergers now keep total momentum and land at the pair's centre of mass, and a black hole takes on the momentum of matter it swallows; each is covered by a regression test.

How it's tested

Last verified run: 105/105 Vitest unit tests; 18/18 local browser smoke checks; Orbito browser checks 16/16 in each of Chromium, Firefox and WebKit; npm audit 0 vulnerabilities. Earlier campaign (not rerun for this release): QA smoke 6/6, 10/10 seeded personas, 100/100 fuzz cases, 12/12 UAT checks, a 600.8 s extended session.

npm run typecheck; npm test (vitest run, src/**/*.test.ts, node environment); npm run build; npm run preview then npm run smoke; node scripts/orbito-check.mjs (ORBITO_BROWSER=firefox|webkit for other engines). npm run verify chains typecheck, test and build.

Limits I've written down

  • Touch emulation does not replace testing on physical touch hardware.
  • Browser zoom edge cases and WebGL context-loss recovery have not been fully verified.
  • The benchmark on an RTX 3050 (P95 7.0 ms) is capped by a 144 Hz display, so it is not maximum GPU throughput.
  • It is an interactive sandbox, not a general-purpose relativistic astrophysics solver.
