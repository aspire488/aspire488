CodeFlowCodeFlow

CodeFlow is a browser-based learning workspace for beginners in C, HTML, CSS and JavaScript, with 73 topics, 132 explained quiz questions, output prediction, step-by-step visualisations, Logic Quest and progress tracking. It is vanilla JavaScript with hash routing and localStorage, installable as a PWA, and needs no account, API key or backend.

shipped, v1.1.0

Why it exists

The PRD says it "teaches introductory programming by making program state visible", for beginner programmers, especially KTU Computer Science students. README tagline: "Learn programming by following the execution, not memorising the syntax.

What I built

Built solo: content data, routing, visualisation and practice engines, screen renderers, service worker, static build and the node:test and Playwright suites.

GitHub lists one contributor on the repository.

How it's put together

  • Content data data/Content only: topicsDB, quizDB, outputPredictionDB, logicQuestDB, knowledgeBase.
  • Core src/core/syntaxHighlighter.js, router.js (route table to screen ids and renderers), app.js (AppState, persistence, delegated events, modal lifecycle, single bootstrap; loads last), theme.js.
  • Engines src/engines/Visualization, output prediction, logic analyzer, Logic Quest, adaptive practice and quiz logic.
  • Screen renderers src/ui/One renderer per screen: dashboard, lesson, quiz, logic, chatbot (study assistant).
  • Static build scripts/build-static.cjsCopies the tree and fails if a referenced script is missing from the artifact.
  • Tests tests/Structural and unit tests on node:test (smoke, unit, highlighter, regression) and Playwright browser suites (e2e, qa, production).

Decisions, and why

  1. Two visualisation mechanisms, authored steps and computed traces, labelled and never mixed silently.

    When a snippet is outside the supported subset, the UI says so; it never pretends to interpret arbitrary C.

  2. The syntax highlighter scans the source once and escapes each plain chunk before wrapping tokens.

    The earlier chained .replace() calls over generated HTML matched inside their own attributes and corrupted the output.

  3. The service worker is network-first for navigations and tolerates individual precache failures.

    So deploys are not served stale; the old install always failed on wrong root-level paths.

  4. The QA suite builds a fresh browser context per persona and measures clipping from scrollWidth.

    One persona's localStorage can never contaminate another, and hidden overflow still fails the check.

The interesting problems

  • Global namespace with no module system

    Classic scripts attach to the global scope, so load order and unique names are part of correctness. Before v1.1.0, three router implementations and four renderVisualization definitions shadowed each other by load order. Tests now fail if any function name is declared twice in src/, a script src is missing, or a router screen id is absent from index.html.

  • The "stuck blur" modal overlay

    The inactive overlay intercepted clicks; it now uses visibility: hidden and pointer-events: none, and the mobile drawer sits above its backdrop (z-index 40 vs 35).

  • Regular-expression hang in the CSS analyzer

    Fixed, with input capped at 10,000 characters and analyzer output escaped.

How it's tested

v1.1.0 release verification: 54 unit tests passed; 84 local Playwright checks passed; 70 production Playwright checks passed; 11 production routes exercised; 0 console errors or failed requests in the final capture.

npm test (node --test on tests/smoke, unit, highlighter, regression .test.cjs); npx playwright install chromium then npm run test:e2e (desktop + Pixel 5); npm run test:qa (persona workflows, adversarial input, storage recovery, overflow); npm run test:e2e:production against the deployment.

Limits I've written down

  • Visualisation computes traces only for the documented examples: a supported for loop, factorial recursion and a pointer demo.
  • The logic analyser is heuristic, not a compiler. The study assistant is rule-based, not an LLM.
  • Logic Quest is a vertical slice. Progress is stored in your browser only.
  • No WCAG certification. Performance has not been independently benchmarked.

Stack

  • Vanilla JavaScript, HTML, CSS (no frontend framework, no runtime dependencies)
  • Vite ^5.4.0 (dev server)
  • @playwright/test ^1.48.0
  • Node built-in test runner (node --test)
  • Service worker + web app manifest
  • Node >=20.19.0
